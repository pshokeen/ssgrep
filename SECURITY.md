# Security Policy

## Reporting a Vulnerability

Please report suspected security vulnerabilities **privately** — do not open
a public GitHub issue for a suspected vulnerability, since that discloses it
to everyone before a fix is available.

Use one of the following channels:

- **GitHub Security Advisories** (preferred): open a
  [private security advisory](https://github.com/pshokeen/ssgrep/security/advisories/new)
  for this repository. This keeps the report, discussion, and any embargoed
  fix in one place, visible only to the maintainer and anyone you invite.
- **Email**: `pshokeen@live.com` (Prateek Shokeen, maintainer).

When reporting, please include:

- a description of the vulnerability and its potential impact;
- steps to reproduce, or a proof-of-concept if you have one;
- the affected version or commit;
- your assessment of severity, if you have one.

## Response Expectations

This is currently a small, single-maintainer project. Response times are
**best-effort, typically within a few business days** for an initial
acknowledgment — this is not a contractual SLA, just the honest expectation
for a project at this stage. If you have not heard back within a couple of
weeks, it is fine to follow up.

## Disclosure

Please give the maintainer a reasonable opportunity to investigate and
release a fix before any public disclosure. Coordinated disclosure timelines
can be discussed case by case through the reporting channel above.

## Supported Versions

ssgrep does not yet have a formal support/backport policy for older
releases. Until one exists, please report vulnerabilities against the
latest released version; the maintainer will note here if that changes.

| Version | Supported |
|---|---|
| Latest release | ✅ |
| Older releases | Best-effort, case by case |
